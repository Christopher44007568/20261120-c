# ORIGIN SHIFT / 大坐标原点重定位实验场

一个无框架、无运行时依赖的 WebGL2 演示。CPU 使用双精度保存百万米级世界坐标，GPU 只接收分区原点与相机相对坐标；相机跨越 512 m 分区边界时更新渲染原点，并实时测量三条渲染路径的差异。

![运行截图](./artifacts/preview.png)

## 运行

```bash
npm start
# 打开 http://127.0.0.1:4173
```

需要支持 WebGL2 的浏览器。也可以使用任意静态文件服务器托管仓库根目录。

```bash
npm test
```

`npm test` 不需要浏览器，直接验证路线过界次数、相对投影抖动、拾取连续性和拾取误差量级。

## 三个对照视图

| 视图 | 上传方式 | 用途 |
| --- | --- | --- |
| 原始单精度 | 绝对世界坐标直接转 FP32；相机平移与顶点均在 GPU 上参与大数相减 | 基线，暴露细线跳动和物体位置偏差 |
| 相机相对 | CPU 双精度世界坐标 − 512 m 分区原点 − 当前渲染原点，只上传小坐标 | 实际采用的原点重定位管线 |
| 双精度参考 | CPU 每帧用 FP64 完成世界变换并生成裁剪空间顶点 | 真值对照，不依赖 GPU 大数精度 |

三块视口共享同一双精度相机、同一条路线和同一组实例。原始视图只量化位置，不量化相机旋转，避免把“方向也被 FP32 破坏”误当成坐标精度问题。

## 场景与交互

- 世界坐标位于 `X ≈ 1,100,288 m`、`Z ≈ 2,300,416 m`。
- 6 座机库、滑行中线、64 m 地面网格、512 m 分区边界、灯柱和 5 台移动载具由 CPU 双精度生成。
- 自动回放沿同一条闭环滑行路线运行 3 圈，跨越 18 次分区边界。
- 拖拽旋转观察方向，滚轮调整俯仰，点击任意视口地面放置世界坐标拾取探针。
- `Space` 暂停/继续，`R` 重放整条路线。
- 拾取探针固定为双精度世界坐标；渲染时每帧重新计算“探针 − 当前渲染原点”，因此原点更新不会改变探针与目标机库的相对位置。

## 指标口径

- **细线像素抖动**：在当前相机前方 18–380 m 的滑行中线上取样，比较每条路径的投影像素与 FP64 投影的最大屏幕距离。
- **拾取坐标误差**：用同一屏幕射线分别以 FP32 相机/相对坐标和 FP64 反投影到地面，计算命中点与 FP64 命中点的米制距离。
- **重定位帧画面跳变**：在渲染原点切换前后各取一帧，扣除相机自身微小位移造成的正确像素位移，再测量锚点残余位移；相对相机与参考值的残差应在 `0.1 px` 以下。

典型自动化结果：

```text
partition crossings: 18
max relative line jitter: 0.002513 px
min raw FP32 line jitter: 1.505 px
max relative relocation jump: 0.011129 px
pick error (relative): 8.08e-06 m
pick error (raw FP32): 5.36e-02 m
```

## 代码结构

- `src/scene.js`：世界常量、路线、机库/标线/载具生成、相机与拾取锚点。
- `src/renderer.js`：三种 WebGL2 绘制路径、静态分区块、实例缓冲与 CPU FP64 参考缓冲。
- `src/metrics.js`：细线抖动、拾取误差、重定位跳变测量。
- `src/app.js`：自动回放、交互、过界记录、图表与 HUD。
- `tests/verify.mjs`：纯 Node 的数值回归检查。

中文界面使用仓库内打包的 Noto Sans SC 子集，离线环境也能完整显示；字体许可见 `assets/fonts/OFL.txt`。
