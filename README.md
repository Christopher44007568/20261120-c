# GPU 内存池 / 资源驻留 / 楼层连通性实验

纯标准库 Python 模拟，无第三方依赖。

## 目录

- `gpupool/allocator.py`：内存池分配器。容量按堆块（默认 32MB）对齐逐块提交，
  内部维护有序空闲段表，支持 best-fit 分配、相邻段合并、压缩整理（compaction）
  与按堆块归还（trim），并统计外部碎片率、高水位峰值、分配失败数。
- `gpupool/residency.py`：资源驻留管理器。区分短生命周期（transient，
  纹理/缓冲等高频增删）与长生命周期（persistent）资源；`recycle` 策略提供
  按尺寸分桶的回收缓存、失活资源惰性驱逐与失败后压缩重试，`naive` 策略不做任何驻留优化。
- `gpupool/workload.py`：确定性事件流（固定随机种子）与三策略对照、
  稳定性长跑、容量压力、碎片整理专项、碎片率曲线等实验。
- `floorplan/layout.py`：网格楼层（墙/房间/走道），生成沿走道两侧排布并开门的
  房间，BFS 验证全房间连通，并输出房间面积与矩形碰撞数。
- `tests/`：17 个 unittest 用例。
- `artifacts/experiment_report.json`：最近一次实验的机器可读结果。

## 运行

```bash
python3 -m unittest discover -s tests -v
python3 run_experiments.py
```

## 指标定义

- 外部碎片率 = 1 − 最大空闲段 / 总空闲字节，越大表示空闲空间越碎、越难容纳大块。
- 峰值提交 = 历史高水位已提交显存；稳态提交 = 整理归还堆块后的当前占用。
- 分配失败 = 容量耗尽（含碎片导致无法满足）的请求次数。

## 主要结论（默认种子，可复现）

- 频繁增删工作负载下，回收缓存命中上百次，配合周期整理使最终碎片率降至 0%。
- 碎片整理专项：交错孔洞场景峰值 96MB → 64MB，稳态 96MB → 32MB，碎片率 75% → 0%。
- 160MB 压力测试：驻留+整理把分配失败从 65 次降到 18 次，失活资源驱逐 14 次。
- 200 tick 长跑碎片率始终收敛、堆块数有界，内存池稳定不发散。
- 楼层 6 个房间碰撞数为 0，BFS 确认走道连通所有房间；无走道负面对照正确判为不连通。
